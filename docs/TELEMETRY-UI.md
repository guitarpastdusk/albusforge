# Stored telemetry monitor

`/live` now reads the session-authorized `/v1/telemetry/devices` fleet, with UUID cursor pagination and explicit never-uploaded, offline and revoked states. `/live/:deviceId` reads detail, provisioned channels and latest samples, then a bounded series. Device UUIDs are shown directly: build names, grouping and widget preferences are not invented. Last packet arrival and sample time are labelled separately; zero is a valid reading.

Both pages require the current session before fetching. The existing server transport forwards allowlisted cookies, uses `cache: no-store`, and keeps gateway credentials off the client. Gateway independently authorizes every telemetry read against current membership. No tenant ID supplied by the UI scopes a query. The existing active-workspace/internal-SSR host behavior remains; tenant-subdomain handoff is not implemented here.

History uses ordinary GET forms, keeping channel, window, resolution and an optional UTC end in the URL. Windows are one hour, 24 hours, seven days or 30 days; shared schema validation rejects raw over 24 hours and minute over seven days before fetching. Rollup endpoints align down to the last complete UTC bucket. Blank end means now on every refresh. The response limit is 2,000; 422 never becomes a truncated chart. A 410 describes expiry and any available-from boundary, and a 503 preserves latest values with a retry action. Pending rollups are explicitly stale/incomplete, including when empty.

The chart places independent dots by actual UTC timestamp across the requested window. It never joins missing readings or substitutes zeros. SVG point titles and an expandable HTML table expose exact sample sequence/ordinal or aggregate count, min, max and last; aggregate values are labelled means. Native labelled form controls, responsive grids, an overflow table, and route loading status support keyboard and narrow screens. Server navigation replaces the whole selected result; no client request race or polling subscription is introduced.

This is a refreshed snapshot monitor, not production streaming or the richer build dashboard. Existing mock dashboard components remain for future integration; these pages use the new telemetry endpoints and do not fall back to simulated device data. Mock mode currently has no stored-telemetry fixtures. Device Ask, rules, historical health, editable names, claim/provisioning and cross-device intelligence require their backend contracts. Production deployment and real-device/browser end-to-end validation remain separate release work.

Validation covers real route selection/admission, fleet pagination, latest zero values retained during history errors, aligned query limits, explicit retention/freshness errors, timestamp placement and exact sequence identity. These are local component/contract tests, not evidence of production connectivity.
